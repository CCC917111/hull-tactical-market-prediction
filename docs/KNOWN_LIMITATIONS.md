# Known limitations

This is an archival course-project implementation. Packaging and runtime fixes do not validate its research conclusions.

1. **Preprocessing precedes the temporal split.** The imputer, variance filter, target-aware `SelectKBest`, correlation filter, Isolation Forest, and winsorization bounds are fitted on all training CSV rows before the final 20% is held out. Future validation observations influence learned transformations, including supervised feature selection. The validation metrics are not leakage-free.
2. **Potential target leakage and train/test timing mismatch.** Only the chosen target and identifiers are dropped. Other outcome fields such as `market_forward_excess_returns` can remain in training. At inference, `lagged_market_forward_excess_returns` and `lagged_risk_free_rate` are renamed to their unlagged names. These do not necessarily have the same information availability. Audit the competition schema and use only information known at prediction time before undertaking a new experiment.
3. **In-sample stacking.** The meta-learner is fitted on base-model predictions for the same rows used to train the base models. It does not use out-of-fold predictions. Use expanding-window out-of-fold predictions for an unbiased redesign.
4. **Validation is used repeatedly.** Ridge alpha selection and tree-model early stopping use the final 20%, which is also used for reporting metrics. An independent untouched test period is absent. The base models are not subsequently refitted on the entire dataset.
5. **Two allocation mappings.** Local CSV predictions use batch-standardized `enhanced_sigmoid`; the Kaggle callback uses `2 / (1 + exp(-20 * prediction))` and returns the mean batch weight. These are different strategies. The competition's batch format and gateway were not available for validation. The callback returns neutral exposure after prediction errors, which can hide failures in competition runs.
6. **Incomplete experiment record.** The report includes standalone Random Forest and LightGBM results not backed by executable baseline scripts in the archive. Its claims of a zero stability gap and eliminated overfitting are historical statements, not conclusions confirmed by this repository. The screenshot shows public score 0.461 and a separate best score 2.058 V4; they must not be conflated.
7. **Original environment unknown.** No versions, data hashes, trained models, logs, or executed notebook were supplied. `requirements.txt` describes the newly tested environment, not the environment that produced the screenshot.
8. **Input assumptions.** Rows must already be chronological. Data must have numeric feature columns and a finite target. All-empty features, too few informative features, tiny datasets, and new categorical schemas are not supported by the historical pipeline. Missing test features are filled with training medians by the working notebook; this is a compatibility fallback rather than a proof that the schemas agree.

A defensible follow-up experiment would split first, fit every transform only on past training rows, remove outcome-derived features, fit the stack on chronological out-of-fold predictions, use one causal weight mapping, and reserve a separate evaluation window. Those research changes have deliberately not been substituted for the original course submission.
